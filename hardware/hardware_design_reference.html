05 — Validation Report

Design checks

PASS

GPIO conflicts: 24 unique pins in use, zero unintended overlaps, none in the reserved 6–11 range, GPIO 5 correctly avoided.

PASS

Voltage levels: RC522 direct 3.3V-to-3.3V (no level shifting needed); HC-SR04 ECHO divider outputs 3.33V, within the 3.6V absolute max.

PASS

Current budget: ≈71mA peak across all 12 LEDs, ≈60mA sensors, ≈26mA RC522 — combined with WiFi TX bursts, ≈350–400mA peak, comfortably inside a typical dev board's onboard regulator capacity.

CHECK

Green LED forward voltage: the guide's current calc assumes Vf≈2.0V; many green LEDs run higher (2.8–3.2V), which would make them noticeably dimmer at 220Ω. Measure actual Vf before final assembly; drop to ~150Ω on green channels only if needed.

FLAGGED

GPIO 2 / GPIO 12 pull-ups: the guide specifies 10kΩ pull-ups to 3.3V on both. GPIO 12 (MTDI) determines flash voltage at boot — pulling it HIGH can select the wrong voltage and prevent boot on most WROOM-32 modules. GPIO 15 is low-risk and fine as specified; GPIO 2 and 12 are not certain failures, but warrant a power-cycle test before final assembly, with pull-down as a fallback if boot becomes unreliable.

PASS

RFID boot interaction: firmware already calls Serial.end() before RC522 init to free GPIO3/UART0 RX — correctly handled.
